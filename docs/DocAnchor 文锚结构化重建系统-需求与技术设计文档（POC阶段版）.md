# DocAnchor 文锚结构化重建系统-需求与技术设计文档（POC阶段版）

## 1. 项目概述

### 1.1 核心目标

针对**多人拼凑、样式混乱、XML结构崩坏、深度嵌套**的脏DOCX文档，实现全自动：文档结构解析、内容纠错、层级归一化、结构重建，最终输出**格式统一、结构严谨、冗余干扰低、符合预置模板规范**的干净DOCX文档。

本版本为**架构优化版**：将系统锚点从Word渲染引擎迁移至PDF，通过同源PDF坐标系消灭跨引擎坐标对齐的核心工程风险，大幅降低自研成本与实现复杂度。本文档为阶段1技术预研POC版设计，支撑核心链路验证与关键风险点攻关，不直接作为全量正式开发的最终验收基准。

### 1.2 适用场景

- 多人协同拼凑Word，无规范样式、手动格式刷泛滥、样式ID冲突
- 文档存在深度嵌套表格、浮动文本框、多栏排版、跨页对象
- 原文档含修订记录、删除线、隐藏文字、冗余元数据干扰
- 原生组件解析层级失效、结构错乱，但页面视觉排版正常的脏文档

### 1.3 核心设计取舍（关键基线）

- **锚定PDF同源坐标系**：放弃对Word原始排版的还原义务，以PDF作为全系统统一坐标与内容基准，消灭跨引擎坐标偏移风险
- **XML前置清洗，DOCX退居辅助角色**：原始DOCX仅负责转换前的XML级元数据清洗，以及作为文字校对的最终权威源，不参与排版与坐标锚定
- **视觉负责结构，PDF文本负责文字**：VLM视觉模型识别页面结构与层级，PDF原生文本层兜底校正文字准确性
- **规则优先、LLM兜底**：高频率固定逻辑用规则实现，模糊歧义场景调用小模型，兼顾速度、成本、稳定性

## 2. 整体系统架构（核心Pipeline）

全流程固定顺序，无分支歧义，可直接代码串行实现：

```
DOCX源文件 → XML级元数据清洗 → LibreOffice headless转PDF → 双路并行解析
                                                                      ↓
                              ┌───────────────────────────────────────────────────┐
                              ▼                                                   ▼
                     VLM分页解析(MinerU原生PDF输入)                  PyMuPDF对象提取
                     (结构/区块/类型/局部层级/坐标)             (文本span+坐标/图片+坐标/表格+坐标)
                              │                                                   │
                              └────────────────── 双路对齐 ────────────────────────┘
                                                │
                                      全局聚合（结构修复+层级归一化）
                                                │
                                      文字双路校验（DOCX为最终权威）
                                                │
                                      模板灌注与文档重建
                                                │
                                      标准化干净DOCX输出
```

**核心双路机制**：

1. 视觉结构路：VLM 基于PDF页面输出区块类型、层级、布局位置，负责结构语义识别
2. 原生文本路：PyMuPDF 提取PDF原生文本层、图片、表格对象，负责文字与资源的精准获取> 
> 两路共享同一PDF页面坐标系，几何天然重合，无跨引擎坐标偏移风险

## 3. 各模块详细设计

### 3.1 前置：XML级清洗与PDF转换模块

#### 3.1.1 功能描述

先对原始DOCX做纯XML层的元数据清洗，从源头移除脏数据；再通过LibreOffice headless转换为标准PDF，作为全系统唯一的排版、坐标、视觉基准；同步提取PDF内所有对象与坐标，支撑后续双路对齐。

#### 3.1.2 技术栈选型

| 环节 | 主选方案 | 备选方案 | 兜底方案 |
| --- | --- | --- | --- |
| XML级清洗 | python-docx + lxml | — | — |
| PDF生成 | LibreOffice headless（跨平台、零授权） | OnlyOffice Document Server | Word COM（Windows虚拟机） |
| PDF对象提取 | PyMuPDF | pdfplumber | — |

#### 3.1.3 XML级元数据清洗（纯规则、无排版操作）

在DOCX转PDF前执行，纯OOXML文本操作，不改动排版与布局，从源头清除脏数据：

1. 接受全部修订：移除修订标记，固化最终文本内容，清除插入/删除状态
2. 删除隐藏文字：移除所有`w:vanish`标记的文本run
3. 删除删除线文本：移除所有带删除线格式的文本run（非修订模式的手动删除线）
4. 删除批注与批注框：清除所有评论、批注与修订作者信息
5. 域代码静态化：可选将域结果固化为文本，清除域代码（MVP阶段默认执行）
6. 清除宏与VBA：移除所有宏、模块与ActiveX控件

#### 3.1.4 PDF生成配置（固定参数、保证一致性）

- 视图配置：关闭修订标记、关闭隐藏文字、关闭批注显示
- 页面配置：嵌入所有字体、固定页边距、固定DPI输出、禁用自适应排版
- 输出规范：单页连续、标准PDF 1.7格式，保留原生文本层
- 降级链路：LibreOffice转换失败 → OnlyOffice转换 → Word COM兜底（仅重度异常文档启用）

#### 3.1.5 PDF对象提取（PyMuPDF）

基于PDF原生文档结构提取所有对象，坐标系与VLM输入完全同源：

- 文本对象：提取文本span、内容、页面坐标、字体属性，按页面输出
- 图片对象：提取内嵌图片、页面坐标、尺寸，导出原始图片资源
- 表格对象：识别表格结构、行列数、单元格坐标与内容，输出单元格矩阵
- 坐标系说明：采用PDF原生页面坐标系（点单位），与VLM输出坐标天然对齐

#### 3.1.6 阶段1 Go/No-Go判定项

POC阶段仅验证一项核心前提，不通过则不进入后续全链路开发：
**LibreOffice转换保真度验证**：基于50篇脏文档语料，验证以下指标：

1. 内容召回率：正文/表格文本召回率≥99%，图片召回率≥98%
2. 分页偏差分布：统计不同脏度文档的分页偏移量，中度脏文档分页偏差≤1行占比≥90%
3. 表格结构保真度：常规表格行列结构准确率≥95%，嵌套表格结构畸变率≤5%

#### 3.1.7 输出数据

- 清洗后DOCX文件
- 标准PDF文件（带原生文本层）
- PDF对象清单：文本、图片、表格三类，带页面坐标与属性
- 转换日志：字体替换记录、分页偏差记录、降级触发记录

### 3.2 VLM分页解析模块（纯视觉方案）

#### 3.2.1 模型选型

- **主选管线**：MinerU（开源文档解析管线，原生支持PDF输入，包含版面分析、表格识别、OCR、公式识别能力）
- **备选模型**：Donut / Pix2Struct，用于特定场景适配
- **选型约束**：直接输入PDF文件，输出区块级坐标与结构化内容；禁止使用全文端到端生成模型，避免不可控的结构漂移

#### 3.2.2 VLM适配层（Adapter）设计

新增Adapter层，将MinerU管线输出归一化为系统定义的标准Block Schema，屏蔽不同模型的输出差异：

1. **结构归一化**：将MinerU的版面块、表格单元、图注、公式等映射为标准block_type，补全缺失字段
2. **坐标对齐**：统一输出PDF原生页面坐标系，与PyMuPDF提取对象坐标系完全一致
3. **二次校验**：对表格行列数、合并单元格、阅读顺序、标题层级做规则级校验，修正明显的输出异常
4. **异常过滤**：剔除越界bbox、重复区块、空内容块，字段缺失自动降级补默认值
5. **版本锁定**：固定MinerU管线版本、配置哈希，所有输出记录模型版本号，支持可复现

#### 3.2.3 标准单页Block结构

每页输出Block数组，单个Block基础字段定义：

- `page_id`：页码
- `block_id`：页内唯一ID
- `bbox`：PDF页面坐标 `[x1, y1, x2, y2]`（点单位，与PyMuPDF同源）
- `block_type`：枚举值【title、paragraph、table、list、image、caption、formula】
- `local_level`：页面局部视觉层级（1-6，对应标题1-6）
- `text`：VLM识别纯文本
- `confidence`：区块识别置信度（0-1）
- `markdown_content`：页内结构化Markdown内容
- `vlm_model_version`：模型/管线版本号

#### 3.2.4 模块固有特性

- 单页独立推理，**无跨页全局上下文**
- 仅保留页内局部结构，跨页表格、段落、列表会被截断
- 局部层级仅基于页面视觉特征，跨页层级会出现漂移错乱

#### 3.2.5 运行时约束与失败兜底

- 运行配置：固定PDF输入参数、模型版本号、推理参数，支持版本追溯
- 输出校验：强制JSON Schema校验，格式错误自动重试2次
- 失败降级：单页解析失败时， fallback 至PyMuPDF文本+规则分块，标记为低置信度
- 置信度阈值：区块置信度低于0.7时，自动进入人工复核队列

### 3.3 全局聚合模块（核心自研模块）

输入：VLM分页Block结果 + PyMuPDF对象辅助信息；输出：全局唯一、层级归一化、跨页合并、阅读流连续的**全局文档树**

#### 3.3.1 子模块1：预处理清洗（纯规则，无LLM）

1. 区块排序：按PDF页面坐标y轴升序、同y轴按x轴升序排列，修正阅读顺序> 
> 说明：PDF文本层存储顺序≠视觉阅读顺序，必须按坐标重排
2. 噪声过滤：剔除页眉、页脚、空区块、分割线等无效内容；判定规则：页面上下5%高度内、重复出现的文本
3. 文本归一化：统一换行符、去除多余空格，保留原始识别文本不做修改
4. 类型校验：校验区块类型与内容匹配度，不匹配标记为异常

#### 3.3.2 子模块2：跨页对象合并（规则优先+小模型兜底）

采用**相邻页滑动窗口**（当前页尾3个块 + 下一页头3个块）检测跨页对象，遵循「宁可漏合、不可错合」原则。

> 
> 说明：分页断点为LibreOffice生成的PDF分页，非原始Word分页。

1. **跨页段落合并**
   - 一级规则判定：页尾区块类型为paragraph，结尾无句末标点（。！？；：”）；下页首区块类型为paragraph；前后段落关键词重叠率≥30%（规则计算，无需LLM）
   - 满足全部规则条件自动合并；规则判定模糊（关键词重叠率15%-30%）时，调用小模型做二元判断，计入单篇LLM调用上限
   - 边界模糊且模型置信度不足时标记待复核，不强制合并
2. **跨页列表合并**
   - 规则判定条件：页尾为有序列表项，编号与下页首列表项编号连续；列表缩进层级一致
   - 中文数字、罗马数字、带括号编号均纳入匹配范围；编号不连续则不合并
3. **跨页表格合并**
   - 规则初筛：列数一致、表头关键词匹配度≥80%，覆盖重复表头、续表标注场景；同步参考PyMuPDF表格识别结果做交叉校验
   - 模型校验：规则通过后调用小模型做二元判断（是否为同一逻辑表格）
   - 特殊场景：合并单元格、表尾说明、无表头表格均纳入识别逻辑
   - 判定为同一表格则合并单元格矩阵；否则保留独立表格，标记待复核

> 
> 跨页表格二元判断小模型契约：
> 
> 
> - 输入：上下两个表格的表头文本、列数、首行内容、页面位置
> - 输出：`{"is_same_table": bool, "confidence": float}`
> - 约束：仅做二元判断，不修改文本；置信度<0.8标记待复核

#### 3.3.3 子模块3：全局标题层级归一化

解决VLM跨页层级漂移、局部层级错乱问题，优先级：**文档自带编号 > 小模型判断 > VLM局部视觉层级**。

1. 标题候选提取：筛选全文档所有title类型Block，汇总为标题候选列表
2. 编号优先解析：正则提取标题内章节编号，覆盖阿拉伯数字（1./1.1）、中文数字（第一章/第一节）、罗马数字、带括号编号、附录等格式，直接映射全局层级
3. 滑动窗口增量校正：窗口大小为连续10个标题，前后重叠2个标题；小模型仅输出**全局层级、父子关联关系、置信度**，禁止改写文本内容
4. 全局一致性校验：每处理5个窗口，触发一次全量层级回溯校验，修正累积漂移；漂移超过阈值则回退并扩大窗口重判
5. 栈结构构建：代码维护全局章节栈，根据输出的层级构建父子从属关系；LLM仅做层级判断，不管控树结构逻辑
6. 异常处理：低置信度标题、无编号且层级存疑的标题，标记为待复核，不强制修正

> 
> 标题层级归一化小模型契约：
> 
> 
> - 输入：连续标题列表（文本、局部层级、页码、编号信息）
> - 输出：`[{"id": str, "global_level": int, "parent_id": str, "confidence": float}]`
> - 约束：禁止改写标题文本；层级只能为1-6整数；无法判定标记confidence<0.5

#### 3.3.4 子模块4：全局阅读流与文档树构建

基于归一化标题树，挂载所有内容块：

- 正文、列表：归属至最近的上级标题节点
- 图片+图注：配对规则为垂直距离最近且位于图片下方/上方的caption区块，距离阈值为图片高度的30%（PDF坐标单位）；一图多注、多图一注等歧义场景标记待复核，绑定为统一图文对象后挂载对应章节
- 合并后跨页表格：作为独立结构化对象挂载对应章节
- 公式：独立挂载对应章节，MVP阶段保留文本识别结果，不做深度结构化重构

最终输出：完整可序列化**全局文档树JSON**（唯一标准输出，供后续灌注使用）

#### 3.3.5 复核回流接口

人工复核修正后的结果支持定向回流，触发局部重算，无需全文档重新跑批：

- 仅修正文本内容：回流至文字校验模块，更新对应节点文本与校验记录
- 修正结构/层级/合并关系：回流至全局聚合模块对应节点，仅重算子树结构与从属关系
- 修正结果同步更新节点的`review_resolution`字段与操作日志，保留全链路可追溯性

### 3.4 文字校验与双路核对模块

#### 3.4.1 核心逻辑

**结构采信VLM，文字优先采信PDF文本层，原始DOCX为最终权威源**。依托同源PDF坐标系，双路对齐复杂度大幅降低，重点解决VLM文字识别错误。

#### 3.4.2 预对齐机制

VLM区块与PDF对象共享同一PDF页面坐标系，几何天然重合，匹配策略从「IoU为主」简化为**文本相似度为主、坐标重叠校验为辅**：

1. **匹配算法**：先按坐标范围粗筛候选对象，再计算文本相似度；采用贪心匹配算法，计算双向匹配度
2. **匹配分级**
   - 强匹配：文本相似度≥0.95 且 坐标范围重叠，视为一一对应
   - 弱匹配：文本相似度0.8~0.95 或 坐标部分重叠，标记为模糊匹配
   - 无匹配：VLM区块无对应PDF文本对象（如图片内文字、艺术字），标记为纯视觉识别
3. **异常降级**
   - 一对多、多对一映射：保留映射关系，记录拆分/合并日志
   - 无原生对应区块：文字校验降级为LLM语义校验，不做原生比对

#### 3.4.3 分层校验规则

1. **关键字段强制双路比对**
   - 覆盖范围：金额、日期、编号、编码、证件号等硬字段（通过正则+实体识别定位）
   - 处理规则：VLM文本与PDF文本不一致时，默认采信PDF文本；若PDF文本与原始DOCX文本存在差异，以DOCX为准，记录`conflict`日志
   - 降权场景：PDF文本来自域代码、修订残留时，降低权重，进入复核队列
2. **普通文本语义校验**
   - 小模型分段通读全文，检测不通顺、歧义、语病
   - 发现异常通过坐标映射定位PDF文本对象，核对修正；无PDF文本依据时，仅标记异常，不自动改写
3. **校验底线**
   - 禁止无原生依据自动改写文本；允许标记异常建议，必须保留溯源路径
   - 所有文字修正最终可溯源至原始DOCX文本

### 3.5 模板灌注与文档重建模块

#### 3.5.1 输入

校正完成、结构归一化的全局文档树

#### 3.5.2 标准样式映射表

基于预置DOCX模板，建立全局样式一一映射关系，输出样式可验证、可复现：

| 全局节点类型 | 模板样式ID | 核心格式规则 | 特殊控制 |
| --- | --- | --- | --- |
| 一级标题 | Heading 1 | 二号、黑体、段前24磅、段后18磅 | pageBreakBefore：章首启用；keepWithNext：与下一段绑定 |
| 二级标题 | Heading 2 | 三号、黑体、段前18磅、段后12磅 | keepWithNext：启用 |
| 三级标题 | Heading 3 | 四号、黑体、段前12磅、段后6磅 | keepWithNext：启用 |
| 正文 | Normal | 小四、宋体、首行缩进2字符、1.5倍行距 | 孤行控制启用 |
| 有序列表 | List Number | 与正文同字号、缩进对齐 | 按章节重启编号 |
| 无序列表 | List Bullet | 与正文同字号、缩进对齐 | 层级缩进差2字符 |
| 表格 | Table Normal | 五号、宋体、边框1磅、单元格居中 | 跨页默认重复表头行；允许行内断字 |
| 图注 | Caption | 五号、宋体、居中、图号连续 | 与上方图片绑定 |
| 图片 | 嵌入式 | 按比例缩放，宽度不超过版心 | 禁止浮动式插入 |

#### 3.5.3 文档重建细则

- 分页重排：输出文档按模板样式重新分页，不受原始PDF/Word分页影响
- 域处理：前置已清除原文档所有旧域代码；目录、页码、页眉页脚按模板重新生成
- 分节控制：按一级标题分节，页码连续；特殊章节可配置单独分页
- 跨页对象：表格跨页自动重复表头；图片禁止跨页截断，自动调整分页位置
- 冗余清理：彻底清除原文档修订、批注、隐藏文字、自定义样式、宏代码

#### 3.5.4 输出规范

- 统一标题层级、字体、字号、行距、缩进，符合模板样式
- 所有跨页对象完整合并，无逻辑截断、无内容重复
- 无冗余修订、隐藏文字、错乱样式、浮动对象错位问题
- 文档结构严谨，章节从属关系清晰，符合标准办公文档规范

### 3.6 小模型通用设计规范

所有调用的小模型统一遵循以下规则：

1. **选型与部署**：优先选用7B/14B参数开源模型本地部署；成本敏感场景可替换为商用内网合规API；单篇文档LLM调用次数上限可配置
2. **输入输出强约束**：所有任务固定Prompt模板、固定JSON Schema；输出格式校验不通过自动重试2次，重试失败标记待复核
3. **温度参数控制**：分类/判断/层级类任务温度=0，保证输出确定性；语义分析类任务温度≤0.3，保留适度灵活性
4. **防幻觉机制**：严格禁止改写原文，仅做判断、分类、异常标注；所有输出带置信度，低置信度结果不自动生效
5. **一致性校验**：关键任务（标题层级、表格合并）支持多轮投票校验，降低随机漂移

## 5. 关键边界规则与避坑策略

1. **元数据处理**：XML层前置清洗+PDF视图配置双重过滤修订、删除线、隐藏文字，从源头降低干扰
2. **跨页对象策略**：宁可漏合、不可错合，模糊场景标记人工复核，不自动篡改结构
3. **层级校正策略**：文档自带章节编号权重 > 小模型判断权重 > VLM局部视觉层级权重
4. **文字纠错底线**：所有文字修正优先溯源PDF文本层，最终权威为原始DOCX，LLM仅做异常发现，不做无依据改写
5. **PDF锚定边界**：系统分页以LibreOffice转换结果为准，不承诺还原Word原始分页；域代码静态化，不保留可编辑域
6. **表格风险控制**：极端嵌套表格以PyMuPDF文本结构为准，VLM视觉结构做参考，不一致进入复核

## 6. 方案核心优势

1. 解决脏文档**样式崩坏、XML层级失效**问题，不依赖原生污染结构
2. **消灭跨引擎坐标对齐风险**：锚定PDF同源坐标系，VLM与原生对象坐标天然重合，移除原架构中P0级自研风险点
3. 大幅降低工程成本：无需自研Word bbox导出链路，PyMuPDF提供成熟对象提取接口，开发量减少30%以上
4. 规避纯VLM方案**文字识别错误、全局结构错乱**的核心硬伤
5. 自动过滤大部分冗余元数据干扰，输出文档干净度高
6. 规则+小模型混合架构，兼顾准确率、速度、稳定性，适合工程落地
7. 跨平台零授权依赖：主链路基于LibreOffice+开源组件，无需Office授权成本

## 7. 非功能需求

### 7.1 兼容性

- 支持绝大多数常规DOCX文档；明确不支持扫描件嵌入Word、宏/VBA文档、加密文档、受保护文档、大量艺术字复杂混排文档
- MVP阶段优先覆盖50页以内、嵌套层级≤3层的轻中度脏文档
- 极端复杂嵌套表格、大量数学公式的学术文档暂不支持

### 7.2 稳定性

- 100页以内常规脏文档无结构崩溃、无内容丢失；超过阈值文档支持分段处理
- 所有模块异常可降级、可追溯，不出现全流程中断
- 批量处理支持断点续跑，任务失败可从断点重试
- PDF转换降级链路完整，LibreOffice失败可自动切换备选引擎

### 7.3 可追溯与可复核

- 所有文字修正、结构调整可溯源原始文档位置与操作日志
- 低置信度内容统一标记，支持人工二次校验与结果回流
- 全链路版本可追溯，支持重复运行结果一致性校验

### 7.4 性能与成本

**性能指标基准硬件：NVIDIA A100 单卡GPU环境；消费级显卡（如RTX 4090）耗时预计增加50%-100%**

- **统计口径**：含XML清洗、PDF转换、VLM解析、全局聚合、文字校验、模板灌注全流程；失败重试计入耗时
- **耗时指标**：100页常规文档P50≤5分钟，P95≤8分钟
- **LLM成本**：单篇文档小模型调用次数≤20次（100页内）
- **幂等性**：同一文档相同参数重复运行，规则处理链路与温度=0的模型任务链路输出一致性≥99.5%；语义校验结果不纳入幂等性统计口径
- **批量处理**：支持队列调度，任务优先级可配置

### 7.5 安全与合规

- 数据本地化：POC阶段全链路本地部署，文档内容、处理日志、中间结果均不流出本地环境，禁止调用外部公网API处理文档内容
- 存储安全：原始文档与处理结果加密存储，访问权限受控
- 脱敏处理：人工复核界面默认隐藏敏感字段，支持按规则脱敏
- 数据销毁：任务完成后可配置自动清理中间文件与临时数据
- 降级合规：若启用商用API兜底，仅允许使用内网部署的合规服务，禁止文档内容出境

## 8. 质量评估与验收标准

### 8.1 评测集与标注规范

#### 评测集构成（POC阶段50篇，正式阶段200篇）

| 脏度等级 | 占比 | 覆盖场景 |
| --- | --- | --- |
| 轻度脏文档 | 40% | 少量样式冲突、简单跨页、轻度修订 |
| 中度脏文档 | 40% | 多人拼凑、手动格式刷、嵌套表格、浮动文本框、跨页表格 |
| 重度脏文档 | 20% | 多栏排版、深度嵌套、大量修订隐藏、复杂域、大量浮动对象 |

#### 标注规范

- 人工基准以**文档语义逻辑**为准，而非原始XML样式；标题层级以章节从属语义为ground truth
- 跨页表格以逻辑上是否为同一表格为判定标准，不以上下文物理位置为唯一依据
- 文字基准以原始DOCX可编辑文本为准，图片内文字单独统计

### 8.2 指标计算口径

| 指标 | 计算口径说明 |
| --- | --- |
| 标题层级准确率 | 全链路径一致（从根节点到当前标题的完整层级路径匹配），非仅末级一致 |
| 章节父子关系F1 | 以节点ID对齐，精确率=正确父子对/输出父子对；召回率=正确父子对/基准父子对 |
| 阅读顺序Kendall τ | 按全文阅读流排序，计算输出顺序与基准顺序的秩相关系数 |
| 表格单元格F1 | 包含合并单元格、空单元格；表头重复不计入错误；按单元格位置+内容匹配 |
| 普通文本CER | 中文字符粒度，标点、全半角统一归一化后计算；纯视觉识别区块单独统计 |
| 人工复核占比 | 分脏度等级分别统计，轻度/中度/重度分别设阈值 |

### 8.3 POC阶段验收目标

| 指标 | 轻度脏文档 | 中度脏文档 | 重度脏文档 |
| --- | --- | --- | --- |
| 标题层级准确率 | ≥95% | ≥92% | ≥85% |
| 章节父子关系F1 | ≥93% | ≥90% | ≥82% |
| 表格行列准确率 | ≥97% | ≥95% | ≥88% |
| 关键字段准确率 | ≥99% | ≥99% | ≥97% |
| 普通文本CER | ≤0.3% | ≤0.5% | ≤1% |
| 人工复核占比 | ≤8% | ≤15% | ≤30% |

### 8.4 通过规则

- POC验收：中度脏文档核心指标达标，重度脏文档核心指标不低于下限，即可通过进入下一阶段
- 不采用badcase一票否决，按批量均值判定；允许存在已知边界case，纳入迭代优化
- POC阶段验收结论仅用于判定是否进入下一研发阶段，不作为最终生产环境的精度承诺

## 9. MVP边界与降级策略

### 9.1 MVP支持范围

- 原生可编辑的DOCX格式文档
- 以正文、标题、表格、普通列表为主的办公文档
- 轻度到中度样式混乱、多人拼凑的文档
- 50页以内、嵌套层级≤3层的文档

### 9.2 MVP排除范围（后续迭代支持）

- 扫描件、图片嵌入的Word文档
- 含大量VBA宏、复杂可编辑域、控件的文档
- 加密、受保护、数字签名的文档
- 极端多栏排版、大量浮动艺术字、复杂矢量图的文档
- 含大量数学公式的学术文档
- 超过200页的超长文档
- 要求还原原始Word分页与可编辑域的场景

### 9.3 降级策略

- PDF转换失败：LibreOffice → OnlyOffice → Word COM兜底，逐级降级并记录日志
- VLM解析失败：降级为PyMuPDF文本+规则分块，标记低置信度
- 双路匹配失败：降级为纯文本相似度匹配，扩大复核范围
- 层级判定失败：保留VLM局部层级，标记人工复核
